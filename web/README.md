# Reflect web

The Reflect web app: Next.js (App Router) with strict TypeScript.

## Where things are

| Path | Holds |
|---|---|
| `../packages/core/` | The headless core the app imports as `@reflect/core/<module>`: the person's stores, the journal and packs. See [its README](../packages/core/README.md). |
| `src/server/` | Server only. `auth.ts` is Better Auth (email and password) on Neon Postgres, and also an OAuth server for a person's own AI (the `@better-auth/mcp` plugin: clients register themselves, the person signs in and allows them on `/consent`, and tokens are bound to `/api/mcp`). `site.ts` fixes the app's public address. `mcp-tools.ts` is what that AI can do: `reflect_guide`, `list_entries`, `write_entry` (today's entry, in the person's words), `get_entry`, `keep_legacy_plan`, `legacy_status`, and for what the person knows `learning`, `add_book` (Open Library's subjects come back only as suggestions), `add_book_subjects`, `set_book_status`, `recall_check` (the person's own words, before seeing any list), `add_courses` (rows the person confirmed from their transcript), `add_credential`, `rate_subject` (the person's rating, never the AI's), `add_input` (a film, talk, conversation or link), `mark_subject` (shown or suggested, never a grasp), `ideas` and `keep_idea` (the person's own ideas with their inputs and recommendations), each a plain function of the person. `learn-store.ts` keeps books, subjects, recalls and grasps (migration 0009): titles, names, recalls and notes sealed, a subject found again by its keyed hash, recalls and grasps never changed, the latest grasp counting, and nothing known until the person rates it. `learn-sources-store.ts` (migration 0010) keeps uploads (a transcript's file and its model draft, or a LinkedIn export's contents, sealed), confirmed courses linked to subjects, credentials with what an issuer's badge said, and vouches (endorsements on subjects, recommendations whole), each kept once. `ideas-store.ts` (migration 0011) keeps inputs beside books (films, talks, conversations, links, each once), subject marks (shown, suggested; append-only, never grasps) and ideas as append-only lines folded by core's `foldIdea`; `sweep-store.ts` keeps the items of a memory sweep the person chose, once each. `legacy-store.ts` carries out a legacy release after the person's death (migration 0008): the plan (trustees, how many must confirm, the wait), each recipient's part sealed, a link per trustee and per recipient (token hashed for lookup, sealed for the person to see again); a release opens with the first trustee confirmation, starts once enough have confirmed, can be stopped by the person or any trustee during the wait, and only then shows each recipient their part. A new plan revokes the old links; refused while a release is open. Telling the person or trustees by email that a release has begun is not built: there is no mail provider yet. `person-store.ts` writes onboarding in one transaction, once per person. `crypto.ts` seals every answer with AES-256-GCM under a key derived per person, and `tag` gives a concept a keyed hash so the same person, act or quality is found again without storing it in the clear. |
| `src/db/migrations/0001_person.sql` | The person's tables. Append-only: a trigger refuses DELETE and any UPDATE except setting `valid_to` once. |
| `src/app/sign-in/`, `src/app/journal/` | Sign up or sign in, and the journal page onboarding leads to. |
| `src/app/api/mcp/`, `src/app/consent/`, `src/app/.well-known/` | The MCP endpoint a person's own AI (Claude, ChatGPT or any MCP client) connects to, the page where the person allows it, and the OAuth discovery documents clients look for. To connect, add `<app address>/api/mcp` as a custom connector in the AI app. |
| `src/app/legacy/` | The person's legacy page (plan, trustee links, any release, and a stop button), a trustee's page (`/legacy/trustee/<token>`: confirm the death, stop, and once released each recipient's link) and a recipient's page (`/legacy/receive/<token>`: their part once released, a plain not-found before). |
| `src/app/learn/` | What you know (`/learn`): subjects you rated as known, your books with what of a read book you have not rated, and a form to keep a book (an ISBN looks it up in Open Library). A book's page (`/learn/book/<id>`): where you are with it, what you remember of it named without looking, its subjects marked named or not, your grasp of each, and Open Library's subjects and contents, shown only after you recall. `/learn` also holds courses (grade beside your grasp, and a transcript upload a model reads with gpt-oss through AI Gateway), credentials (an optional Open Badges check) and a LinkedIn export upload. `/learn` also holds subjects shown and suggested (apart from known), films, talks, conversations and links, and the memory sweep: the prompt for your own AI and a place to paste its reply. `/learn/upload/<id>` is where you confirm a transcript's rows, choose what of a LinkedIn export to keep, or check a memory sweep's items. |
| `src/app/ideas/` | Your ideas (`/ideas`), outputs kept apart from Learn. An idea's page (`/ideas/<id>`) shows it in your latest words with earlier wordings, what it came from and maybe from, and recommendations grouped from supports to opposes, with forms to restate it, name an input, add a recommendation, or drop one. |
| `e2e/` | Playwright runs of the journal, Me and Learn on desktop and phone, with axe-core checks, and the whole MCP connection (`mcp.spec.ts`: register, sign in, allow, token, tools, then a legacy plan kept by the AI, confirmed by a trustee and received). `SHOTS_DIR=<dir>` saves screenshots. |

## Environment

Set by name only, never committed: `DATABASE_URL` (the Neon project `reflect`, pooled), `BETTER_AUTH_SECRET`, `REFLECT_DATA_KEY` (32 random bytes, base64), and `BETTER_AUTH_URL` in deployments (also the address MCP tokens are bound to; `REFLECT_URL` overrides it). `REFLECT_RATE_LIMIT=off` turns the sign-in rate limit off for the browser tests only.

## Commands

- `pnpm install`
- `pnpm migrate` creates the Better Auth tables (including the OAuth tables for MCP clients) and the person's tables.
- `pnpm test` runs the app's, the core's and the CLI's tests.
- `pnpm bundle export --user <id> --out <file>` and `pnpm bundle import <file> --user <id>` move one person's journal between Postgres and a bundle file (see `../packages/core/src/bundle.ts`), against whichever branch `DATABASE_URL` names. Import goes only into an empty journal.
- `pnpm typecheck`
- `pnpm dev`, then open http://localhost:3000.
- `pnpm build`
- `pnpm build && pnpm e2e` runs the browser tests (Playwright 1.63 with Chromium).
