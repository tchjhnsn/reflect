# Reflect web

The Reflect web app: Next.js (App Router) with strict TypeScript.

## Where things are

| Path | Holds |
|---|---|
| `../packages/core/` | The headless core the app imports as `@reflect/core/<module>`: the person's stores, the journal and packs. See [its README](../packages/core/README.md). |
| `src/server/` | Server only. `auth.ts` is Better Auth (email and password) on Neon Postgres, and also an OAuth server for a person's own AI (the `@better-auth/mcp` plugin: clients register themselves, the person signs in and allows them on `/consent`, and tokens are bound to `/api/mcp`). `site.ts` fixes the app's public address. `mcp-tools.ts` is what that AI can do: `reflect_guide`, `list_entries`, `write_entry` (today's entry, in the person's words), `get_entry`, `keep_legacy_plan`, `legacy_status`, and for what the person knows `learning`, `add_book` (Open Library's subjects come back only as suggestions), `add_book_subjects`, `set_book_status`, `recall_check` (the person's own words, before seeing any list), `add_courses` (rows the person confirmed from their transcript), `add_credential`, `rate_subject` (the person's rating, never the AI's), `add_input` (a film, talk, conversation or link), `mark_subject` (shown or suggested, never a grasp), `ideas` and `keep_idea` (the person's own ideas with their inputs and recommendations), each a plain function of the person. `learn-store.ts` keeps books, subjects, recalls and grasps (migration 0009): titles, names, recalls and notes sealed, a subject found again by its keyed hash, recalls and grasps never changed, the latest grasp counting, and nothing known until the person rates it. `learn-sources-store.ts` (migration 0010) keeps uploads (a transcript's file and its model draft, or a LinkedIn export's contents, sealed), confirmed courses linked to subjects, credentials with what an issuer's badge said, and vouches (endorsements on subjects, recommendations whole), each kept once. `claims-store.ts` (migration 0012) keeps claims (text and holders sealed, found again by a keyed hash, maybe under a subject) and the person's stances as new rows, the latest counting. `ideas-store.ts` (migration 0011) keeps inputs beside books (films, talks, conversations, links, each once), subject marks (shown, suggested; append-only, never grasps) and ideas as append-only lines folded by core's `foldIdea`; `sweep-store.ts` keeps the items of a memory sweep the person chose, once each. `legacy-store.ts` carries out a legacy release after the person's death (migration 0008): the plan (trustees, how many must confirm, the wait), each recipient's part sealed, a link per trustee and per recipient (token hashed for lookup, sealed for the person to see again); a release opens with the first trustee confirmation, starts once enough have confirmed, can be stopped by the person or any trustee during the wait, and only then shows each recipient their part. A new plan revokes the old links; refused while a release is open. Telling the person or trustees by email that a release has begun is not built: there is no mail provider yet. `person-store.ts` writes onboarding in one transaction, once per person. `crypto.ts` seals every answer with AES-256-GCM under a key derived per person, and `tag` gives a concept a keyed hash so the same person, act or quality is found again without storing it in the clear. |
| `src/db/migrations/0001_person.sql` | The person's tables. Append-only: a trigger refuses DELETE and any UPDATE except setting `valid_to` once. |
| `src/app/sign-in/` | Sign up or sign in. Signing in lands on home. Not used in open mode (below). |
| `src/app/api/mcp/`, `src/app/consent/`, `src/app/.well-known/` | The MCP endpoint a person's own AI (Claude, ChatGPT or any MCP client) connects to, the page where the person allows it, and the OAuth discovery documents clients look for. To connect, add `<app address>/api/mcp` as a custom connector in the AI app. |
| `src/app/page.tsx`, `src/app/home-tiles.ts` | Home (`/`): your life as objects, per the interface design. MINE shows 18 tiles, several opening one app; a tile's tone is in action, in thought or unstated, from what you have (Learn from your books), never guessed. Only Learn opens; the other tiles are not built yet in this design. OURS shows the 6 shared-space tiles, not built yet. The plus button opens the chat; the folder (the journal) is not built yet in this design. |
| `src/app/chat/`, `src/app/api/chat/` | The chat behind the plus button (`/chat`), on the pattern of json-render's own chat example (vercel-labs/json-render, `examples/chat`): AI SDK `useChat` streams from `/api/chat`, and the message shows text, the tool steps and the cards in order. The model (gpt-oss-120b through AI Gateway when deployed, Ollama Cloud otherwise; `src/server/chat-model.ts`) reads only your Learn summary and calls tools (`show_shelves`, `show_claims`, `search_library`, `browse_library_class`, `propose_claim`). Unlike the example, the model never writes a spec: each tool fetches your records and Reflect builds the cards (`spec.ts`, from the components in `catalog.ts`, drawn in `registry.tsx`) and streams them as one json-render spec part. A library card's Add to shelves and a proposed claim's Accept are the only taps that write (`addBookFromChat`, `keepClaimFromChat` in `actions.ts`); each card shows busy, done or failed itself. The conversation is not saved; leaving the page ends it. |
| `src/app/learn/` | Learn in the new design (`/learn`): MY SHELVES (books as rectangles and subjects as circles on the 21 Library of Congress shelves, dark known, grey learning, light registered, from your book status and grasp only; a book opens a side panel to say want to read, reading or read), LIBRARY (the whole of Open Library by class or search, with Add to shelves) and CLAIMS (belief, disbelief, suspension of judgment, with holders cited and stances kept). |
| `src/app/fonts.ts` | The new design's typeface, IBM Plex Mono. The new pages sit under the `.nd` class in `globals.css`: white, black, one face. |
| `archive/2026-11-12-old-app/` | The old app, archived when the new design replaced it (Torian, 2026-11-12): journal, ideas, Me, legacy, the old Learn pages and their e2e tests. Not routed and not type-checked; the stores they used stay in `src/server/` because the MCP tools still use them. |
| `e2e/` | The whole MCP connection (`mcp.spec.ts`: register, sign in, allow, token, tools, then a legacy plan kept by the AI, confirmed by a trustee and received; the trustee and receive pages are archived, so that last part fails until they come back). `SHOTS_DIR=<dir>` saves screenshots. |

## Environment

Set by name only, never committed: `DATABASE_URL` (the Neon project `reflect`, pooled), `BETTER_AUTH_SECRET`, `REFLECT_DATA_KEY` (32 random bytes, base64), and `BETTER_AUTH_URL` in deployments (also the address MCP tokens are bound to; `REFLECT_URL` overrides it). `REFLECT_RATE_LIMIT=off` turns the sign-in rate limit off for the browser tests only.

## Commands

- `pnpm install`
- `pnpm migrate` creates the Better Auth tables (including the OAuth tables for MCP clients) and the person's tables.
- `pnpm test` runs the app's, the core's and the CLI's tests.
- `pnpm bundle export --user <id> --out <file>` and `pnpm bundle import <file> --user <id>` move one person's journal between Postgres and a bundle file (see `../packages/core/src/bundle.ts`), against whichever branch `DATABASE_URL` names. Import goes only into an empty journal.
- `pnpm typecheck`
- `pnpm dev`, then open http://localhost:3000. The dev server runs in open mode: no sign-in, everything belongs to one owner account (`src/server/open-mode.ts`). Vercel previews do too, since they sit behind the Vercel team's own sign-in; production keeps sign-in. `REFLECT_OPEN=off` or `on` overrides it.
- `pnpm build`
- `pnpm build && pnpm e2e` runs the browser tests (Playwright 1.63 with Chromium).
