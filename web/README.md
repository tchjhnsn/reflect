# Reflect web

The Reflect web app: Next.js (App Router) with strict TypeScript.

## Where things are

| Path | Holds |
|---|---|
| `../packages/core/` | The headless core the app imports as `@reflect/core/<module>`: the person's stores, the journal and packs. See [its README](../packages/core/README.md). |
| `src/server/` | Server only. `auth.ts` is Better Auth (email and password) on Neon Postgres, and also an OAuth server for a person's own AI (the `@better-auth/mcp` plugin: clients register themselves, the person signs in and allows them on `/consent`, and tokens are bound to `/api/mcp`). `site.ts` fixes the app's public address. `mcp-tools.ts` is what that AI can do: `reflect_guide`, `list_entries`, `write_entry` (today's entry, in the person's words), `get_entry`, `keep_legacy_plan`, `legacy_status`, and for what the person knows `learning`, `add_book` (Open Library's subjects come back only as suggestions), `add_book_subjects`, `set_book_status`, `recall_check` (the person's own words, before seeing any list), `add_courses` (rows the person confirmed from their transcript), `add_credential`, `rate_subject` (the person's rating, never the AI's), `add_input` (a film, talk, conversation or link), `mark_subject` (shown or suggested, never a grasp), `ideas` and `keep_idea` (the person's own ideas with their inputs and recommendations), each a plain function of the person. `learn-store.ts` keeps books, subjects, recalls and grasps (migration 0009): titles, names, recalls and notes sealed, a subject found again by its keyed hash, recalls and grasps never changed, the latest grasp counting, and nothing known until the person rates it; every book status change is also kept as a new row (migration 0013, `learn_book_status`) for the log. `learn-sources-store.ts` (migration 0010) keeps uploads (a transcript's file and its model draft, or a LinkedIn export's contents, sealed), confirmed courses linked to subjects, credentials with what an issuer's badge said, and vouches (endorsements on subjects, recommendations whole), each kept once. `claims-store.ts` (migration 0012) keeps claims (text and holders sealed, found again by a keyed hash, maybe under a subject) and the person's stances as new rows, the latest counting. `ideas-store.ts` (migration 0011) keeps inputs beside books (films, talks, conversations, links, each once), subject marks (shown, suggested; append-only, never grasps) and ideas as append-only lines folded by core's `foldIdea`; `sweep-store.ts` keeps the items of a memory sweep the person chose, once each. `legacy-store.ts` carries out a legacy release after the person's death (migration 0008): the plan (trustees, how many must confirm, the wait), each recipient's part sealed, a link per trustee and per recipient (token hashed for lookup, sealed for the person to see again); a release opens with the first trustee confirmation, starts once enough have confirmed, can be stopped by the person or any trustee during the wait, and only then shows each recipient their part. A new plan revokes the old links; refused while a release is open. Telling the person or trustees by email that a release has begun is not built: there is no mail provider yet. `person-store.ts` writes onboarding in one transaction, once per person. `crypto.ts` seals every answer with AES-256-GCM under a key derived per person, and `tag` gives a concept a keyed hash so the same person, act or quality is found again without storing it in the clear. |
| `src/db/migrations/0001_person.sql` | The person's tables. Append-only: a trigger refuses DELETE and any UPDATE except setting `valid_to` once. |
| `src/app/sign-in/` | Sign up or sign in. Signing in lands on home. Not used in open mode (below). |
| `src/app/api/mcp/`, `src/app/consent/`, `src/app/.well-known/` | The MCP endpoint a person's own AI (Claude, ChatGPT or any MCP client) connects to, the page where the person allows it, and the OAuth discovery documents clients look for. To connect, add `<app address>/api/mcp` as a custom connector in the AI app. |
| `src/app/page.tsx`, `src/app/home-tiles.ts` | Home (`/`): your life as objects, per the interface design. MINE shows 18 tiles, several opening one app; a tile's tone is in action, in thought or unstated, from what you have (Learn from your books), never guessed. Only Learn opens; the other tiles are not built yet in this design. OURS shows the 6 shared-space tiles, not built yet. The plus button opens the chat; the folder (the journal) is not built yet in this design. |
| `src/app/chat/`, `src/app/api/chat/` | The chat behind the plus button (`/chat`), on the pattern of json-render's own chat example (vercel-labs/json-render, `examples/chat`): AI SDK `useChat` streams from `/api/chat`, and the message shows text, the tool steps and the cards in order. The model (gpt-oss-120b through AI Gateway when deployed, Ollama Cloud otherwise; `src/server/chat-model.ts`) reads only your Learn summary and calls tools (`show_shelves`, `show_claims`, `search_library`, `browse_library_class`, `propose_claim`). Unlike the example, the model never writes a spec: each tool fetches your records and Reflect builds the cards (`spec.ts`, from the components in `catalog.ts`, drawn in `registry.tsx`) and streams them as one json-render spec part. A library card's Add to shelves and a proposed claim's Accept are the only taps that write (`addBookFromChat`, `keepClaimFromChat` in `actions.ts`); each card shows busy, done or failed itself. The conversation is kept message by message (`keepChatMessage` in `journal-store.ts`: one record per chat, marked by `@reflect/core/chat-journal`, the chat's id as its id; your message before the answer, Reflect's reply when it finishes, words only). Past chats are in the chat history (`/chat/history`, `src/app/chat/history/`), read-only, apart from the journal; continuing a past chat is not built. |
| `src/app/journal/`, `src/server/work-store.ts`, `src/app/api/journal/export/` | The journal (`/journal`), opened by the folder icon and the Journal and Ideas tiles: the library of everything you write, as a writing editor (Torian, 2026-11-12 18:48Z). Create opens the prompt library (`/journal/new`, templates in `@reflect/core/works`): a blank page, or a template for a kind of thinking (object writing, examining a belief, an essay, a decision, a plan, a letter, what you want the world to know). A work opens in the editor (`/journal/w/[id]`, Tiptap with Markdown): title, then the page, saved on its own a moment after you stop typing and on Cmd or Ctrl+S. Each save that changes something is a new version in `work_version` (migration 0015), sealed and never changed. "Write about it" on a log act starts a work quoting it. Entries written before the editor stay readable (`/journal/entries/[id]`). Import brings Markdown or text files in as works (`workFromFile`: a leading `# ` heading is the title, else the file name). Export gives one bundle file with the entries and every work as its latest Markdown. Journals sit inside the domains of a life (Torian, 2026-11-12 21:28Z): each domain has a page (`/journal/d/[domain]`) with the works filed in it and what you believe there, and a work started from a domain page is filed there; the editor's header files a work in a domain or in none (`work_domain`, migration 0017). Learn is the source of what a domain holds (Torian, 2026-11-13 03:19Z): a Learn subject is placed in a domain once from its page (`subject_domain`, migration 0018, `src/server/subject-domain-store.ts`), and the subject's claims and books show there under "From Learn"; a belief under a placed subject takes that domain in the book unless the belief itself was placed. Select a passage in any work and "Mark as a belief": an ideal (what is best, as you would pray for it) or a practical belief (what is best for you now, which names the ideal it serves, an existing one or new words that become one, and the circumstances it is for), with its domain, its origins (Aristotle's seven causes, `@reflect/core/origins`) and who else holds it, each with a citation. It is kept as a Learn claim (stance belief) tied to the work (`claim_kind`, `claim_origin`, migration 0017). Beliefs not yet marked either can be marked from their domain page; claims kept in Learn can be placed from the book. The book of your life (`/journal/book`, `src/server/book-store.ts`, `@reflect/core/book`) is compiled live, a chapter per domain in chart order: ideals, then practical beliefs, then beliefs not yet marked, then once held. "Compile an edition" keeps it as a dated memoir in the journal. Placements and sources are append-only rows (migration 0016). The step-by-step reflecting screens are archived (`archive/2026-11-12-reflecting-form/`); the item statechart stays in `@reflect/core/items` and `src/server/item-store.ts`. |
| `src/app/log/`, `src/server/log-store.ts` | The log (`/log`, the list icon on home): what you did in the tiles, kept by the apps and never written by you. `logActs` reads Learn's own records each time (each book's kept status changes, migration 0013, else its added, start and finish days; claim stances; grasps) and `@reflect/core/log` turns them into acts; nothing is copied. The page groups them by your own day in the browser. Books shelved before 0013 show only their shelving, start and finish. Each act has a "Write about it" link that starts a journal work quoting it. Not built: other tiles. |
| `src/components/`, `src/lib/utils.ts`, `src/app/globals.css` | Reflect's look (chosen 2026-11-12): shadcn components (`src/components/ui/`) with Tailwind 4 (`postcss.config.mjs`) and shadcn's neutral theme in `globals.css`, Inter as the face. The chat uses Vercel's AI Elements (`src/components/ai-elements/`). `src/components/segmented.tsx` draws URL views (Mine/Ours, Learn's tabs) as shadcn's tabs list. The mono look and the old paper styles are archived (`archive/2026-11-12-old-app/globals.css`; the mono design whole in `archive/2026-11-12-mono-design/`). |
| `src/app/learn/` | Learn in the new design (`/learn`): MY SHELVES (books as rectangles and subjects as circles on the 21 Library of Congress shelves, dark known, grey learning, light registered, from your book status and grasp only; a book opens a side panel to say want to read, reading or read), LIBRARY (the whole of Open Library by class or search, with Add to shelves) and CLAIMS (belief, disbelief, suspension of judgment, with holders cited and stances kept). |
| `archive/2026-11-12-old-app/` | The old app, archived when the new design replaced it (Torian, 2026-11-12): journal, ideas, Me, legacy, the old Learn pages and their e2e tests. Not routed and not type-checked; the stores they used stay in `src/server/` because the MCP tools still use them. |
| `e2e/` | The whole MCP connection (`mcp.spec.ts`: register, sign in, allow, token, tools, then a legacy plan kept by the AI, confirmed by a trustee and received; the trustee and receive pages are archived, so that last part fails until they come back). `SHOTS_DIR=<dir>` saves screenshots. |

## Environment

Set by name only, never committed: `DATABASE_URL` (the Neon project `reflect`, pooled), `BETTER_AUTH_SECRET`, `REFLECT_DATA_KEY` (32 random bytes, base64), and `BETTER_AUTH_URL` in deployments (also the address MCP tokens are bound to; `REFLECT_URL` overrides it). `REFLECT_RATE_LIMIT=off` turns the sign-in rate limit off for the browser tests only.

## Commands

- `pnpm install`
- `pnpm migrate` creates the Better Auth tables (including the OAuth tables for MCP clients) and the person's tables.
- `pnpm test` runs the app's, the core's and the CLI's tests.
- `pnpm bundle export --user <id> --out <file>` and `pnpm bundle import <file> --user <id>` move one person's journal between Postgres and a bundle file (see `../packages/core/src/bundle.ts`), against whichever branch `DATABASE_URL` names. Import goes only into an empty journal.
- `pnpm typecheck`
- `pnpm dev`, then open http://localhost:3000. The dev server runs in open mode: no sign-in, everything belongs to one owner account (`src/server/open-mode.ts`). Vercel previews do too, since they sit behind the Vercel team's own sign-in; production keeps sign-in. `REFLECT_OPEN=off` or `on` overrides it.
- `pnpm build`
- `pnpm build && pnpm e2e` runs the browser tests (Playwright 1.63 with Chromium).
