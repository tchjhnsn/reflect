# Reflect web

The Reflect web app: Next.js (App Router) with strict TypeScript.

## Where things are

| Path | Holds |
|---|---|
| `../packages/core/` | The headless core the app imports as `@reflect/core/<module>`: the person's stores, the journal and packs. See [its README](../packages/core/README.md). |
| `src/server/` | Server only. `auth.ts` is Better Auth (email and password) on Neon Postgres, and also an OAuth server for a person's own AI (the `@better-auth/mcp` plugin: clients register themselves, the person signs in and allows them on `/consent`, and tokens are bound to `/api/mcp`). `site.ts` fixes the app's public address. `mcp-tools.ts` is what that AI can do: `reflect_guide`, `list_entries`, `write_entry` (today's entry, in the person's words), `get_entry`, `keep_legacy_plan`, `legacy_status`, and for what the person knows `learning`, `add_book` (Open Library's subjects come back only as suggestions), `add_book_subjects`, `set_book_status`, `recall_check` (the person's own words, before seeing any list), `add_courses` (rows the person confirmed from their transcript), `add_credential`, `rate_subject` (the person's rating, never the AI's), `add_input` (a film, talk, conversation or link), `mark_subject` (shown or suggested, never a grasp), `ideas` and `keep_idea` (the person's own ideas with their inputs and recommendations), `add_item` and `add_lesson` (an item on a way of learning and what it taught, the lesson in the person's words), each a plain function of the person. `learn-store.ts` keeps books, subjects, recalls and grasps (migration 0009): titles, names, recalls and notes sealed, a subject found again by its keyed hash, recalls and grasps never changed, the latest grasp counting, and nothing known until the person rates it; every book status change is also kept as a new row (migration 0013, `learn_book_status`) for the log. `learn-sources-store.ts` (migration 0010) keeps uploads (a transcript's file and its model draft, or a LinkedIn export's contents, sealed), confirmed courses linked to subjects, credentials with what an issuer's badge said, and vouches (endorsements on subjects, recommendations whole), each kept once. `claims-store.ts` (migration 0012) keeps claims (text and holders sealed, found again by a keyed hash, maybe under a subject) and the person's stances as new rows, the latest counting. `ideas-store.ts` (migration 0011) keeps inputs beside books (films, talks, conversations, links, each once), subject marks (shown, suggested; append-only, never grasps) and ideas as append-only lines folded by core's `foldIdea`; `sweep-store.ts` keeps the items of a memory sweep the person chose, once each. `legacy-store.ts` carries out a legacy release after the person's death (migration 0008): the plan (trustees, how many must confirm, the wait), each recipient's part sealed, a link per trustee and per recipient (token hashed for lookup, sealed for the person to see again); a release opens with the first trustee confirmation, starts once enough have confirmed, can be stopped by the person or any trustee during the wait, and only then shows each recipient their part. A new plan revokes the old links; refused while a release is open. Telling the person or trustees by email that a release has begun is not built: there is no mail provider yet. `person-store.ts` writes onboarding in one transaction, once per person. `crypto.ts` seals every answer with AES-256-GCM under a key derived per person, and `tag` gives a concept a keyed hash so the same person, act or quality is found again without storing it in the clear. |

## Environment

Set by name only, never committed: `DATABASE_URL` (the Neon project `reflect`, pooled), `BETTER_AUTH_SECRET`, `REFLECT_DATA_KEY` (32 random bytes, base64), and `BETTER_AUTH_URL` in deployments (also the address MCP tokens are bound to; `REFLECT_URL` overrides it). `REFLECT_RATE_LIMIT=off` turns the sign-in rate limit off for the browser tests only.

## Commands

- `pnpm install`
- `pnpm migrate` creates the Better Auth tables (including the OAuth tables for MCP clients) and the person's tables.
- `pnpm test` runs the app's, the core's and the CLI's tests.
- `pnpm bundle export --user <id> --out <file>` and `pnpm bundle import <file> --user <id>` move one person's journal between Postgres and a bundle file (see `../packages/core/src/bundle.ts`), against whichever branch `DATABASE_URL` names. Import goes only into an empty journal.
- `pnpm typecheck`
- `pnpm dev`, then open http://localhost:3000. The dev server runs in open mode: no sign-in, everything belongs to one owner account (`src/server/open-mode.ts`). Vercel previews do too, since they sit behind the Vercel team's own sign-in; production keeps sign-in. `REFLECT_OPEN=off` or `on` overrides it.
- `pnpm build`
- `pnpm build && pnpm e2e` runs the browser tests (Playwright 1.63 with Chromium).
