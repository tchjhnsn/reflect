# reflect CLI

The command line over one person's instance in a folder, usually a private git repository the person owns. Node 22.18 or later runs it as is: `node packages/cli/reflect.ts <command>`. The plan is `docs/design/HEADLESS_REFLECT_2026-11-10.md`.

| Command | Does |
|---|---|
| `init --name <name>` | Starts a vault any editor can open (Obsidian, VS Code), laid out as the Ventures of a Lifetime: `life/`, `needs/`, `learn/`, `work/` (each venture a Naive venture, left to Naive's own checks), `belonging/` (`friends/`, `groups/`, `standing/`), `line/`, `household/` (`members/`, `home/`, `money/`), `community/`, `polis/` and `legacy/` (`wishes.md`, `bucket-list.md`, `letters/`), each with a README that explains it. Beside them: `reflect.json` (`"layout": "vault"`), `memory.jsonl`, `person.json`, `journal/`, `reflections/`, `concepts/`, `documents/`, `telos/`, `intents/`, a `.gitignore` for Obsidian's workspace files, and `.github/workflows/reflect.yml`, which runs [the Action](../../action/action.yml). Refuses a folder that already is one. An instance made before the vault (records under `people/<id>/`) still works. |
| `upgrade` | Moves a vault made on 2026-11-10 (`ventures/household`, `work`, `community`, `friendship` and `library/`) onto the lifetime folders (`friendship` goes to `belonging/friends`, `library` to `learn`), never over a file already there, adopts the moved files in memory, and adds the missing folder guides. |
| `need <need> <how> [--provider <who>] [--runway 30d] [--note <text>]` | Keeps how one of the eight needs (food, water, shelter, health, transport, income, knowledge, safety) is met now: `self-provided`, `stocked` (with a runway), `supplied` or `cared-for`, by `self`, `market`, `nature`, `polis` or `kin`. Writes `needs/<need>.md`; each change adds a line and earlier ones stay. |
| `passage <region> <state> [--on YYYY-MM[-DD]] [--note <text>]` | Keeps a move in your life, in one of the statechart's regions: `provide` (learning, working), `belonging` (affiliating, gaining-status) or `line` (seeking-a-mate, pair-bond, raising-children, caring-for-kin). Appends to `life/passages.jsonl` and rebuilds `life/state.json`, the latest in each region by when it happened. Only the person keeps a passage. |
| `legacy [prompt] [text]` | With no prompt, offers one for what you want to survive you (after the Dignity Therapy questions and the ethical will: your life story, what you are proud of, what you want known, what you learned, your hopes for the people you love, how you want to be remembered, and more). With a prompt and text (argument or stdin), keeps it as an open journal entry with `legacy: true` and the prompt in its front matter. |
| `spark [--minutes 1\|5\|10\|15 \| --sentence]` | Object writing (Pat Pattison): prints a concrete noun, how long to write (5 minutes unless told), and to stay with the senses. |
| `spark <noun> [text] [--minutes N \| --sentence] [--date YYYY-MM-DD]` | Keeps what was written on that noun, from the argument or stdin, as a closed entry with `spark` and `concept: "[[noun]]"` in its front matter, and makes `concepts/<noun>.md` the first time, so Obsidian's backlinks list every entry on the noun. |
| `write [text] [--date YYYY-MM-DD]` | Writes an entry, from the argument or stdin, and prints its id. |
| `learn` | What you know, by your own account. **Known**: subjects whose latest grasp you gave is teach, explain or gist. **Shown** (someone saw you show it) and **Suggested** stay apart from known until you rate them. **Films**, **Talks** and **Conversations** list those inputs. **Books**: each book, its status and dates, and for a book you read, the subjects you have not rated since (a book read but not rated counts as read, not as known). **Aspire** and **Need**: subjects you want, each ready or naming what to learn first. **Possible next**: subjects on your map whose prerequisites you know (the fringe of knowledge space theory). |
| `learn film <title> [--kind] [--year] [--by] [--status want\|watching\|watched\|abandoned\|referenced] [--subjects a,b]`, `learn talk <title> --speaker <who> [--on] [--where] [--url]`, `learn conversation <about> --with <a;b> [--on]` | Inputs beside books, in `learn/films/`, `learn/talks/` and `learn/conversations/`. `learn resource` also takes `post`, `thread` and `newsletter`, and a link's `source` (x, substack, reddit, youtube) is read from it. |
| `learn sweep`, `learn sweep <reply file>`, `learn sweep --keep <1,2 \| all>` | The memory sweep. With nothing, prints the prompt to paste into your AI. With its reply, writes `learn/sweep.draft.json` and lists each item with whether you said it or the AI inferred it. `--keep` keeps the chosen ones: books, films, talks, links, conversations, courses, credentials, subjects as `shown by` or `suggested by` lines, and ideas in `ideas/` (an input the AI only inferred becomes maybe from). Nothing sets your grasp. |
| `source`, `source add <name> <folder> [--exclude <path,*.ext>]`, `source index <name>`, `source prompt <name> [--limit N]`, `source tag <name> <reply file>`, `source tag <name> --keep <1,2 \| all>`, `source <name>` | Your other folders, pointed at instead of moved in. `add` names a folder outside the vault in `sources.json` and indexes it (fingerprints in `.reflect/index/`, leaving out hidden folders, dependencies and anything that looks like a secret). `prompt` prints what to give your own AI: it reads the files and says where each belongs. `tag` reads its reply into a draft. `--keep` turns the chosen ones into pointer lines on the right notes (a book, film, talk, link, conversation, subject or idea) and lines in `sources/<name>.md`; a document goes on the custody checklist with the file as its `where`; entries and ventures are mapped only. The files never move. `source` shows each folder's placed, open, changed and missing files, and `check` names any placed file that changed or vanished. |
| `idea`, `idea <title> [statement] [--from <input>]... [--maybe <input>]... [--how] [--related <stance>:<thing> --by <who> [--note]]... [--drop <thing>]... [--on]` | Your own ideas, outputs kept apart from `learn/`, in `ideas/<title>.md`. An input is a vault note (`learn/books/politics`), a title you kept (looked up in books, films, talks, resources, conversations, subjects, ideas, journal and concepts), or your own words. A recommendation is placed supports, extends, parallels, challenges or opposes, with who suggested it, and becomes an input only when you name it with `--from`. With no title, lists your ideas. |
| `learn find <title or author>` | Looks a book up in Open Library (openlibrary.org, no key) and lists title, authors, year and ISBN. |
| `learn book <title> [--isbn N] [--by <a;b>] [--status want\|reading\|read\|abandoned] [--subjects a,b] [--on <date>]` | Keeps a book in `learn/books/<title>.md`. Reading sets `started`, read sets `finished`. On a book you read, asks you to name its subjects without looking before rating them. With `--isbn N --lookup`, fills authors from Open Library, saves its catalog entry as `learn/books/<title>.openlibrary.json`, and shows its subjects and table of contents. Its subjects are suggestions; you keep the ones that fit with `--subjects`. |
| `learn recall <book> [text]` | The recall check. With no text, asks you to name the book's key subjects without looking. With text (argument or stdin), adds a dated recall line to the book note, says which of its subjects you named (by matching words, no model) and which you did not, shows its contents from Open Library if saved, then asks you to rate each. |
| `learn transcript <file.txt\|file.pdf>`, `learn transcript --keep <1,2 \| all>` | A model (gpt-oss, through AI Gateway or Ollama Cloud) drafts the courses on a transcript into `learn/courses/transcript.draft.json`. A row is offered only when its title, and its grade when given, are really in the transcript. Prints the rows; `--keep` makes the chosen ones courses (`learn/courses/<term>-<code>.md`, the school's record as given), each linked to a subject of the same title that you rate like any other. `learn` then shows each course's grade beside what you say you kept. A PDF needs the unpdf package. |
| `learn credential <name> --issuer <who> [--issued] [--expires] [--url] [--subjects a,b] [--check]` | Keeps a certificate, license or badge in `learn/credentials/`. `--check` reads an Open Badges link and records what the issuer's badge says; checking is optional. |
| `learn linkedin <export folder or zip> [--keep all \| endorsements,recommendations,certifications,skills]` | Reads LinkedIn's data export (LinkedIn's API gives other apps only a name and an email). Without `--keep`, shows who endorsed which skill, recommendations, certifications and listed skills. With it: endorsements become dated vouch lines on subjects, recommendations are kept whole in `learn/vouches/`, certifications become credentials, and listed skills become subjects with no grasp. Vouches never set your grasp; `learn` lists subjects vouched for that you have not rated. A zip needs the fflate package. |
| `learn grasp <subject> <teach\|explain\|gist\|forgot> [--book <title>] [--note] [--on]` | Adds a dated grasp line to `learn/subjects/<subject>.md`: could teach it, could explain the key ideas, remember the gist, or don't remember it. Only you set it, and the latest by date counts. |
| `learn aspire <subject>`, `learn need <subject> --for <what>` | What you want of a subject. A need names what it is for. `--requires a,b`, `--part-of x` and `--same-as wikidata:Q<n>`, `lcsh:sh<n>` or `esco:<uri>` place it in the graph. |
| `learn resource <name> --kind <kind> [--url] [--subjects a,b] [--by] [--platform <id>] [--status]` | Keeps any other link for what you want to learn in `learn/resources/`: a video, channel, article, course, podcast, paper, lab or site. A platform must be connected first. |
| `release` | Your release plan, `legacy/release.json`: the trustees who may confirm your death, how many must confirm, how many days of waiting follow in which you or any trustee can stop it, and what each person receives. Only the legacy folder and journal entries marked `legacy: true` can ever be given; the rest of the journal and reflections never can, and `check` fails a plan that tries. Prints what each person would receive and what the plan still lacks. The Reflect app carries it out: ask your AI, connected to Reflect, to send the plan with `keep_legacy_plan`. |
| `release trustee <name> --contact <c>`, `release give <legacy/... \| legacy-entries> --to <name> --contact <c>`, `release terms [--confirmations N] [--wait <days>]` | Add a trustee, give something to someone, or set the terms (2 confirmations and 30 days unless set). |
| `documents` | The custody checklist for official documents, by group (identity, education, household, money, health, legal): for each one not yet checked, how it is normally kept today and what we recommend (keep the paper safe, store it digitally, or connect the service that holds it), and which connections hold it. The documents themselves need not be in the vault. |
| `documents <type> <custody> [--where <text>] [--connection <id>]` | Checks one off: `original`, `digital-copy`, `connection` (with a connection that holds it), `missing` or `not-applicable`. Writes `documents/<type>.md`: front matter for the current state and one line per check-off, so earlier ones stay. |
| `connect <id> --name <name> --kind vault\|issuer\|portal\|platform [--holds <type,type>]` | Records a service that holds documents for you, such as a secure vault or a school's credential service, or a learning platform you use, such as Khan Academy, Udemy, Coursera or Fanout, in `connections/<id>.json`. No credentials are stored, and Reflect never copies a document from it or reads your progress there (not built). Running it again adds to what it holds. |
| `add <entry> [text]`, `close <entry>` | Adds to an open entry, or closes it. |
| `list` | The entries, newest first. |
| `read [entry] [--pending]` | Asks the reader (Jev, with gpt-oss for self-terms) for its guesses and writes `reflections/<entry>.draft.json`. A draft is never a record and is not in memory. `--pending` reads every entry with no labeling and no draft. Needs `TYPESAFEAI_API_KEY` or `AI_GATEWAY_API_KEY` (and `OLLAMA_API_KEY` to find self-terms without a gateway key). |
| `keep [entry] [--all]` | Keeps a draft as the person left it: `chosen` is the elements they say were part of the entry, and each self-term's `basis` and `keep` are theirs. Each decision is recorded against the reader's guess (confirmed, added, rejected, corrected), then the draft is removed. |
| `export [--out <file>] [--moving-to <where>]` | The whole journal as a bundle (`packages/core/src/bundle.ts`), with times and decisions. `--moving-to` then sets `moved_to` in `reflect.json`, so writes here are refused. |
| `import <bundle>` | Imports a bundle into this instance's empty journal. |
| `check [--adopt]` | Fails on a broken `memory.jsonl` chain, a `reflect.json` that is not an instance config, or a grant that names `journal`, `entries`, `reflections` or `_private`. Lists records written outside reflect (any file in the vault's folders, never `.obsidian/` or `.github/`; by hand, say in Obsidian or the GitHub app); `--adopt` records them in memory as they are. |

Every command takes `--dir <instance>` (default `.`). Writes are refused once `reflect.json` has `moved_to`.

`reflect.test.ts` tests it; `pnpm test` in `web/` runs it. Not built yet: `encrypt: "age"`. A bundle holds the journal only; Me's facts and holds are not in it yet.

## In a GitHub repository

Push the instance to a **private** repository and add `TYPESAFEAI_API_KEY` (or `AI_GATEWAY_API_KEY`) and `OLLAMA_API_KEY` as repository secrets. On each push to `main` the workflow runs `action/action.yml`:

1. It refuses to run in a public repository.
2. `check`.
3. `keep --all` for drafts that reached `main` (a merged pull request), then `check --adopt` for entries written by hand, committed to `main`.
4. `read --pending` onto the branch `reflect/drafts`, and a pull request "Reflect on new entries" if none is open. The pull request is the hold gate: edit the drafts in it and merge to keep them, or close it to keep nothing.
